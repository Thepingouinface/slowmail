Docker

« command not found » ou « Cannot connect to the Docker daemon »

Docker n'est pas installé, ou il n'est pas lancé.

  • Mac et Windows : ouvrez l'application Docker Desktop (ou OrbStack) et attendez que l'icône de la baleine cesse de bouger. Puis recommencez la commande.
  • Linux : sudo systemctl start docker. Si vous lisez « permission denied », ajoutez-vous au groupe docker avec sudo usermod -aG docker $USER, puis fermez et rouvrez votre session.
Windows : « la virtualisation est désactivée » ou une erreur WSL

Docker Desktop a besoin de la virtualisation et de WSL 2.

  1. Ouvrez le Gestionnaire des tâches (Ctrl + Maj + Échap), onglet Performances, puis Processeur : la ligne « Virtualisation » doit indiquer « Activé ».
  2. Si elle est désactivée, activez-la dans le BIOS/UEFI de l'ordinateur (option nommée « Intel Virtualization Technology », « VT-x », « SVM » ou « AMD-V » selon la marque). La manipulation varie d'un modèle à l'autre : cherchez « activer la virtualisation » avec la marque de votre ordinateur.
  3. Installez WSL : ouvrez PowerShell en administrateur et tapez wsl --install, puis redémarrez.
Une erreur « yaml: … » ou « mapping values are not allowed »

Le fichier docker-compose.yml a été abîmé en le modifiant. Les causes habituelles : un guillemet effacé, un décalage des espaces en début de ligne, des tabulations à la place d'espaces, ou un éditeur qui a enregistré en texte enrichi (TextEdit sur Mac : Format, puis « Convertir au format texte »).

Le plus sûr : régénérez le fichier avec le générateur (il écrit les guillemets et les caractères spéciaux à votre place), ou retéléchargez le fichier modèle et remplissez-le de nouveau, en ne changeant que ce qui est entre les guillemets.

Démarrage

« port is already allocated » ou « address already in use »

Un autre programme utilise déjà le port 8080 de votre ordinateur. Dans docker-compose.yml, changez le premier nombre de la ligne des ports :

      - "127.0.0.1:8081:8000"

Puis docker compose up -d, et ouvrez http://localhost:8081. Gardez 127.0.0.1 et le 8000 final tels quels. (Le générateur propose ce port dans ses réglages avancés.)

Le statut n'affiche jamais « healthy »

Comptez jusqu'à deux minutes la première fois. Au-delà, regardez ce que SlowMail dit :

docker compose logs --tail 80

Les causes les plus fréquentes : un fichier docker-compose.yml abîmé (voir ci-dessus), un port déjà utilisé, ou un disque plein. Si l'état est unhealthy alors que l'interface s'ouvre, le planificateur n'a pas encore battu : patientez et rechargez.

« pull access denied », « unauthorized » ou « manifest unknown »

Docker n'arrive pas à télécharger l'image de SlowMail. Vérifiez que vous êtes connecté à Internet et que la ligne image: du fichier n'a pas été modifiée (retéléchargez le fichier si besoin). Si l'erreur persiste, signalez-la avec le message complet : il se peut que l'image ne soit pas accessible publiquement.

Connexion

« SLOWMAIL_PASSWORD n'est pas défini » ou mot de passe refusé
  • Après toute modification de docker-compose.yml, il faut relancer docker compose up -d : sans cela, SlowMail garde les anciennes valeurs.
  • Le mot de passe doit être entre guillemets, sans espace en trop. Un $ s'écrit $$.
  • Après cinq essais ratés, la page vous fait attendre une minute.
  • Mot de passe oublié : il est dans votre fichier docker-compose.yml. Vous pouvez le changer, puis relancer docker compose up -d.
Le bandeau du haut est rouge : « dernier passage du scheduler » ancien

Le planificateur n'a pas tourné depuis plus de 10 minutes : l'ordinateur était en veille, ou Docker arrêté. Ouvrez Docker, vérifiez avec docker compose ps, et attendez une minute. Rien n'est rattrapé en rafale : les créneaux manqués sont replanifiés dans votre plage d'envoi.

Envoi

Rien ne part

Passez cette liste dans l'ordre :

  1. L'interrupteur général est-il à "true" dans docker-compose.yml, et avez-vous relancé docker compose up -d ? Sinon le bandeau affiche « Envois désactivés ».
  2. La campagne est-elle Active (et non en brouillon ou en pause) ?
  3. Le mode simulation est-il décoché ? En simulation, rien ne part, c'est fait pour ça.
  4. Sommes-nous dans la plage horaire, un jour autorisé, qui n'est pas un jour férié ? Le bandeau indique le « prochain envoi prévu ».
  5. Le quota du jour est-il déjà atteint ? Les envois, simulés ou réels, comptent.
  6. Une pause « Disjoncteur » ? Voir plus bas.
« M'envoyer un test » est refusé

La raison est affichée. Les cas fréquents : l'interrupteur général est encore à "false" ; MAIL_FROM_ADDRESS est vide ; le modèle contient une variable inconnue ; la ligne choisie ne partirait pas (une variable vide sans valeur de secours).

Une erreur SMTP s'affiche (identifiants, connexion, expéditeur refusé)
  • « 535 », « authentication failed », « Authentication credentials invalid » : MAIL_USERNAME ou MAIL_PASSWORD est faux. Vérifiez en vous connectant à votre messagerie en ligne avec les mêmes valeurs. Pensez au $ à doubler.
  • « Connection could not be established », « timed out » : MAIL_HOST ou MAIL_PORT est faux, ou votre réseau bloque l'envoi (certains réseaux d'entreprise ou publics). Essayez sur un autre réseau.
  • « 553 », « sender address rejected », « not owned by user » : l'adresse de MAIL_FROM_ADDRESS n'est pas autorisée avec cette boîte. Utilisez l'adresse de la boîte elle-même.
  • Port et sécurité : le port 465 va avec MAIL_SCHEME: "smtps", le port 587 avec "smtp".

SlowMail n'affiche jamais votre mot de passe dans ces messages.

La campagne est en pause avec la raison « Disjoncteur »

Trois échecs d'envoi de suite : SlowMail s'arrête plutôt que d'insister. La raison est affichée en haut de la campagne et dans l'onglet Journal. Corrigez la cause (le plus souvent les identifiants), puis cliquez sur Reprendre.

Mes mails arrivent dans les indésirables

Cela dépend surtout de votre domaine et de votre réputation, pas de SlowMail. Voir la page Bon usage : authentification du domaine (SPF, DKIM, DMARC), volumes faibles, texte sobre.

Données

Mes campagnes ont disparu

Elles sont dans le volume Docker slowmail_slowmail-data. Vérifiez qu'il existe avec docker volume ls. Les commandes qui le détruisent sont docker compose down -v et la suppression du volume dans Docker Desktop : ne les utilisez pas sans sauvegarde. Redémarrer, mettre à jour ou déplacer le dossier slowmail ne les efface pas.

Restaurer une sauvegarde

À faire seulement si vous avez perdu ou abîmé vos données. La restauration remplace tout le contenu actuel de SlowMail par celui de la sauvegarde : ce qui a été fait depuis est perdu.

Dans le dossier slowmail, avec le fichier de sauvegarde choisi dans le dossier sauvegardes (remplacez slowmail-AAAAMMJJ-HHMMSS.sqlite par son nom) :

docker compose stop
docker compose cp sauvegardes/slowmail-AAAAMMJJ-HHMMSS.sqlite slowmail:/data/restauration.sqlite
docker compose run --rm --no-deps --user root --entrypoint sh slowmail -c "rm -f /data/database.sqlite-wal /data/database.sqlite-shm && mv /data/restauration.sqlite /data/database.sqlite && chown www-data:www-data /data/database.sqlite && chmod 600 /data/database.sqlite"
docker compose start

Au redémarrage, le journal d'une campagne active peut signaler une « interruption détectée » : c'est normal (le planificateur n'a pas tourné entre la sauvegarde et maintenant), et rien n'est rattrapé en rafale.

Je veux changer mon mot de passe ou mes réglages de messagerie

Modifiez docker-compose.yml, enregistrez, puis docker compose up -d. Vos campagnes ne sont pas touchées.

Demander de l'aide

Si rien de tout cela ne règle votre problème, ouvrez un ticket en indiquant votre système, ce que vous avez fait et le message d'erreur exact. Vous pouvez joindre la sortie de ces deux commandes :

docker compose ps
docker compose logs --tail 80
Avant de poster quoi que ce soit

Relisez le texte et effacez tout mot de passe, et ne joignez jamais votre fichier docker-compose.yml tel quel : il contient vos identifiants.
